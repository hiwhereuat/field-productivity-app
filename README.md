# Field Productivity App

Мобильное приложение для управления задачами полевых сотрудников.  
**Кандидатский код: `SA-RN-1234`**

## Основные возможности
- Создание, редактирование и удаление задач с обязательными полями (title, description, due date, location).
- Валидация ввода с понятными сообщениями об ошибках.
- Поддержка вложений (изображения из галереи), хранение файлов локально.
- Сортировка задач по дате добавления, due date, статусу.
- Полноценный лог операций (создание, редактирование, смена статуса, вложения, удаление, синхронизация) — общий и на экране задачи.
- Локальные push‑уведомления за 30 минут до дедлайна (с fallback‑уведомлением, если времени меньше). Демо‑режим (30 секунд) для тестирования.
- Карта с маркерами задач (требуется API‑ключ Google Maps, подключается при сборке).
- Автономная работа (все данные хранятся локально через AsyncStorage).
- Синхронизация с mock‑сервером (json‑server): ручная кнопка «Sync Now», автоматическая при старте и восстановлении сети.
- Индикация статуса синхронизации (точка + текст у каждой задачи).
- Светлая и тёмная темы с переключателем.
- Адаптивная вёрстка (SafeAreaView), иконки в таб‑баре, индикатор загрузки.

## Установка и запуск (разработка)
1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/ТВОЙ_ПОЛЬЗОВАТЕЛЬ/field-productivity-app.git
   cd field-productivity-app
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Запустите Expo (development‑сборка):
   ```bash
   npx expo start --dev-client
   ```
   Приложение откроется на подключённом устройстве или эмуляторе.

## Сборка APK
- Локальная debug‑сборка:
  ```bash
  npx expo run:android
  ```
  APK будет находиться в `android/app/build/outputs/apk/debug/app-debug.apk`.
- Production‑сборка через EAS Build (рекомендуется для финальной версии):
  ```bash
  eas build -p android --profile preview
  ```
  **Важно:** для работы карты Google Maps необходимо добавить API‑ключ в `app.json` (секция `android.config.googleMaps.apiKey`) или использовать EAS Secrets (`eas env:create`).

## Mock‑сервер (json‑server)
1. Перейдите в папку `mock-server`:
   ```bash
   cd mock-server
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Запустите сервер:
   ```bash
   npm start
   ```
   Сервер слушает `http://localhost:3000`. Для доступа из эмулятора выполните проброс порта:
   ```bash
   adb reverse tcp:3000 tcp:3000
   ```

## Архитектура
- **State management:** React Context + useReducer (`TaskContext`).
- **Локальное хранилище:** AsyncStorage (задачи, глобальная история, метаданные удалений).
- **Синхронизация:** `syncEngine.ts` (загрузка/выгрузка через REST, last‑write‑wins, обработка удалений).
- **Уведомления:** `expo-notifications` (кастомный сервис).
- **Карта:** `react-native-maps` с Google Maps (API‑ключ вносится при сборке).
- **Навигация:** React Navigation (стек + табы).
- **Тема:** `ThemeContext` (светлая/тёмная).

## Известные ограничения и trade‑offs
- Карта требует API‑ключа Google Maps; без него карта не отображается.
- Push‑уведомления не работают в Expo Go (SDK 53+), только в development/production сборке.
- Геокодирование не реализовано, координаты вводятся вручную или через GPS.
- Синхронизация использует стратегию «last‑write‑wins».
- Поддерживаются только изображения в качестве вложений.
- Синхронизация при старте при отсутствии сервера не вызывает ошибок, оставляя локальные данные неизменными.
